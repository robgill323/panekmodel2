# E-14 real-data smoke run

Manual end-to-end run with **real model weights** against **real YouTube
videos** through the server API. Not part of the CI suite. Script kept at
`scratchpad/smoke.py` (not shipped); this file is the record.

- **Date:** 2026-09-10 · **Commit:** feature/cleanup-hardening
- **Models:** `all-mpnet-base-v2` embeddings, `cardiffnlp/twitter-roberta-base-sentiment-latest` sentiment
- **Settings:** 30 s chunks, `detect_people=true`, Whisper fallback off

## Input

| URL | Outcome |
|---|---|
| `aircAruvnKk` (3Blue1Brown, "But what is a neural network?") | analyzed |
| `rfscVS0vtbw` (freeCodeCamp, "Learn Python — Full Course") | analyzed |
| `THIS_IS_BAD` (deliberately invalid) | skipped — "No caption track available…" |

The invalid URL was skipped with a plain-language reason and the batch
continued, which is the partial-failure behaviour the design calls for.

## Wall clock

| Point | Elapsed |
|---|---|
| fetch + chunk + embed + sentiment complete (2 videos, 625 chunks) | ~40 s |
| BERTopic fit over the combined 625 chunks | ~50 s |
| **run reported `done`** | **324.6 s** |

**Finding — the progress screen goes quiet for the last ~4.5 minutes.** Every
stage reported `done` by ~50 s, but the run did not finish until 324.6 s. The
unaccounted interval is people/entity detection (NLTK NER over 625 chunks),
which runs after the topic fit and **has no stage of its own**. A researcher
watching this sees all five stages complete and then waits four and a half
minutes with no indication the app is still working — exactly the "progress,
not spinners" promise the design makes. Recorded, not fixed: adding a stage
changes the progress contract and the SPA, which is outside this task's scope.
Recommended as a follow-up. Workaround today: turn off entity detection.

Two claims this run settles that were previously only assumed:

1. **`model_produces_neutral` is genuinely `True`** with the new default. The
   3-class model really does emit neutral on real speech, so the default swap
   is validated against real data and not just a label-set check.
2. **Outlier reassignment fires on real data** — 68 of the long video's 586
   chunks were reassigned. The earlier bundle recorded this as an unverified
   assumption (E-19) because HDBSCAN produced no outliers on any synthetic
   corpus. It is now observed, and those chunks correctly report a null
   `topic_prob`.

Representative-excerpt selection also behaves as designed: the top excerpt for
T0 has `topic_prob = 1.0`, i.e. ranked by assignment confidence rather than by
sentiment extremity.
